# Reflect

**不是每笔小修都要复盘。** 先用复杂度 + 根因深度过门槛，再决定记一笔还是做架构反思。细则对齐 `../references/reflect.md`。

匹配：「排查完沉淀」「复盘」「架构反思」「这次改完要不要记一笔」。

## 步骤（原样抄到 todo）

1. **过门槛，再动手。** 对照下方三档。低档直接 `skip: 局部小修` 或写一行，不要做架构反思。
2. **沉淀只写证据 + 可复用规则。** 根因、如何发现、如何防止再犯。这不是日记，不写心情、不写流水账。
3. **中档：更新指针。** 模式可复用就改对应 reference / playbook 的一句指针，让下次能摸到。
4. **高档：架构反思，不偷改范围。** 写清破了哪条不变量、更好的边界、后续债。需要重写/拆模块就提议下一张 `feat.md` / `research.md`，禁止在本卡里默默开干。
5. **生产配置不动。** 复盘过程禁止直接改生产环境配置。

## 门槛

- **低**：局部 typo / 显而易见的 one-liner → skip 或一行备注；不做架构反思。
- **中**：中等改动 / 同类 bug 再现 / 追到才看清 → 短写根因、发现方式、预防；可复用则更新 reference/playbook 指针。
- **高**：跨模块 / 抽象错了 / 系统性 → 架构反思（不变量、边界、后续债）；范围膨胀就另开 feat/research。

**回复：** 档位与理由、沉淀了什么（或 skip）、架构结论（若有）、建议的下一张卡。
