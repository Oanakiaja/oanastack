# Research

**先摸清再动手。** 问的是调研 / 摸底 / 根因调查时，先把证据和选项摊开，不要直接滑进 `feat.md` / `bugfix.md`。

匹配：「调研」「摸底」「先查一下」「根因调查」「有哪些方案」「为什么会这样」（尚未要求开做）。

## 步骤（原样抄到 todo）

1. **收束问题。** 要回答什么、不回答什么、已有线索。写清停止条件。
2. **搜证据，不搜感觉。** 读代码 / 日志 / 复现路径 / 既有文档。每条结论挂来源；没有来源的标成假设。
3. **画选项。** 可行路径、代价、风险、未知。不要只推一条「我觉得最好」。
4. **给结论，停在门槛前。** 推荐下一步是 `feat.md` / `bugfix.md` / 再调研 / 不做。未完成调研不要开写实现。
5. **生产配置只读。** 可以读、可以对比，禁止直接改生产环境配置。

## 不做

- 不借调研偷偷开 feature 或改行为。
- 不引入新 CLI / Graphite。worktree 需要时用 `oana`，本卡默认只读。

**回复：** 问题陈述、证据清单、选项对比、推荐下一步、未决未知。
