# Review

**你只负责看 diff、写可执行的评论。** 这不是 babysit：不推 CI、不合入、不代人改到变绿。

匹配：「review 这个 PR」「看一下 diff」「给评论」「code review」。盯绿 / 处理冲突 / 回完评论还要推 CI 的走 `babysit.md`。

## 步骤（原样抄到 todo）

1. **读意图。** 这个 PR 要解决什么、边界在哪。对照描述与 diff，对不上先问。
2. **看风险。** 正确性、回归面、并发/数据、权限。发现有人要直接改生产环境配置，拦下来。
3. **看风格。** 对照 `../references/code-style.md`。drive-by 改名/重构、clever 一行、注释噪声、无关清理一律拒。
4. **看验证。** 有没有对准行为的测试或复现证据。「编译过」不够。缺证据就要求补，不要自己去刷 CI。
5. **写可执行评论。** 每条说清位置、问题、期望改动或问题。nits 标成 nit。没有问题就明确 LGTM / 有保留。
6. **停在评论。** 不 push、不 rebase、不 `gh pr merge`、不代为变绿。

## 不做

- 不当成 `babysit.md` 去清冲突 / 刷 CI。
- 不 merge / land / ship（owner-only）。

**回复：** 意图是否对齐、风险、风格（对照 `code-style.md`）、测试缺口、评论摘要（或 LGTM）、需要作者拍板的点。
