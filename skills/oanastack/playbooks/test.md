# Test

**验证要有证据，「编译过」不是验收。** 先定目标，再跑，再记录。

匹配：「跑一下验证」「补测试」「怎么证明修了」「验收」。开 feature / 修 bug 的验证步也可以抄这里。

## 步骤（原样抄到 todo）

1. **写验证计划。** 要证明什么、怎样算失败、覆盖哪些路径（含不做什么）。
2. **跑目标验证。** 单测 / 复现路径 / 关键输出，对准计划，不要整仓空跑。
3. **留下证据。** 命令、关键输出、head SHA。失败就记失败，不要用「应该没问题」顶替。
4. **对照验收。** 计划里的项逐条 PASS / FAIL。编译成功、lint 过、CI 还在跑都不等于验收通过。

## 不做

- 不把「能编译」写成验收。
- 不为了凑绿去改生产环境配置。
- 不引入新 CLI / Graphite。

**回复：** 计划、跑了什么、证据、逐条结果、未覆盖的风险。
