# 复盘

按复杂度 + 根因深度决定要不要沉淀，不要每笔小修都写一篇。步骤卡见 `../playbooks/reflect.md`。

- **低**：局部 typo / 显而易见 one-liner → 可 skip 或一行；不做架构反思。
- **中**：同类再现 / 追到才看清 → 短写根因、发现方式、预防；模式可复用则更新 reference / playbook 指针。
- **高**：跨模块 / 抽象错误 / 系统性 → 架构反思：哪条不变量破了、更好的边界、后续债。不要在复盘里默默重写；需要的话另开 `feat` / `research`。

沉淀是证据 + 可复用规则，不是日记。复盘过程禁止直接改生产环境配置。
